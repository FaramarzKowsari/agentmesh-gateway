# Execution Plan: OpenAI Responses API

Status: active

## Objective

Add a protocol-neutral representation for Responses API input items and streaming events, then expose `/v1/responses` without coupling the gateway service to OpenAI-specific event names.

## Work packages

1. Define normalized input-item and output-event types.
2. Add deterministic parser/renderer fixtures for text-only requests.
3. Add `/v1/responses` non-streaming route.
4. Add SSE lifecycle events with strict ordering tests.
5. Add function-call and function-output items.
6. Build a Codex CLI compatibility fixture using a local fake upstream.

## Acceptance gates

- no live API key in default tests
- all existing Chat Completions and Messages tests remain green
- event ordering covered by fixtures
- provider failures before stream commit can fall back; failures after commit cannot
- update `docs/product-specs/compatibility.md` when behavior is verified
