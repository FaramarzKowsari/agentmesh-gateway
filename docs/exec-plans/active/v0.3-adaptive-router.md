# Execution Plan: v0.3 Adaptive Router

Status: active

## Objective

Evolve AgentMesh from a static weighted router into a reproducible constrained routing system that can support research-quality experiments over cost, latency, quality, reliability, and quota pressure without ever selecting a protocol- or capability-infeasible provider.

## Core invariant

Optimization happens only over the feasible provider set.

```text
all configured providers
  -> model + circuit constraints
  -> protocol-losslessness constraints
  -> capability constraints
  -> feasible providers
  -> policy / learned ranking
```

No later optimization stage may reintroduce a provider removed by a hard feasibility gate.

## Work packages

1. **Explicit capability gate** — in progress in issue #23
   - declared provider capabilities
   - adapter-derived backward-compatible defaults
   - request capability derivation
   - filtering before scoring
   - admin observability
2. **Token-normalized cost accounting**
   - record input/output token usage when providers report it
   - configurable per-provider/model token prices or normalized cost coefficients
   - avoid fabricated usage when an upstream does not report tokens
3. **Latency distribution tracking**
   - retain EWMA for fast routing state
   - add bounded recent samples or streaming quantile estimates for p50/p95 analysis
   - keep deterministic test clocks/fixtures
4. **Quota pressure model**
   - explicit configured quota windows and observed consumption
   - hard exhaustion gate plus soft pressure signal
5. **Policy simulation CLI**
   - replay recorded/synthetic request traces without live providers
   - compare ordered, latency, cost, quality, balanced, and experimental policies
   - export deterministic result tables suitable for research notebooks
6. **Benchmark-derived quality profiles**
   - store versioned benchmark evidence separately from runtime state
   - no invented quality numbers; profiles must identify benchmark provenance
7. **Adaptive policy research layer**
   - evaluate constrained contextual bandit or multi-objective policies only after deterministic simulation is available
   - compare against static baselines under identical traces

## Acceptance principles

- no paid API key required for the default test/simulation path
- all experiments reproducible from committed configs/traces or clearly documented external datasets
- protocol and capability constraints are hard safety/validity gates
- missing usage/quality observations remain missing rather than being silently invented
- routing decisions expose enough diagnostics to explain why a provider was eligible and how it was ranked
- CI remains green on Python 3.11, 3.12, and 3.13

## Research outputs enabled by this plan

Once simulation and benchmark profiles exist, the repository can support reproducible comparisons such as:

- cost-constrained latency minimization
- quality-constrained cost minimization
- quota-aware routing under bursty workloads
- regret of adaptive policies versus static baselines
- sensitivity to capability constraints and provider failures

Any reported result must come from an actual committed experiment or reproducible external dataset; this plan does not predeclare performance gains.
