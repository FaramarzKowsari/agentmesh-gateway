# Execution Plan: v0.3 Adaptive Router

Status: validation

## Objective

Evolve AgentMesh from a static weighted router into a reproducible constrained routing system that can support research-quality experiments over cost, latency, quality, reliability, and quota pressure without ever selecting a protocol- or capability-infeasible provider.

## Core invariant

Optimization happens only over the feasible provider set.

```text
all configured providers
  -> model + circuit constraints
  -> protocol-losslessness constraints
  -> capability constraints
  -> quota exhaustion constraint
  -> feasible providers
  -> static or offline adaptive ranking
```

No optimization stage may reintroduce a provider removed by a hard feasibility gate.

## Accounting invariant

`cost_hint` is a configured heuristic for the current static routing score. It is not observed spend. Observed runtime cost uses upstream-reported token counts plus explicitly configured token prices. Missing observations remain missing rather than being converted to zero or estimated from text length.

## Latency invariant

`latency_ewma_ms` remains the current live routing signal. p50/p95 are bounded recent-success evidence for diagnostics and simulation. Percentile measurement does not silently change the production `latency` or `balanced` objective.

## Quota invariant

Configured request quota is a deterministic local control model. It counts outbound provider attempts and can remove an exhausted provider from the feasible set. It does not claim to mirror upstream billing, token-rate, or private rate-limit counters.

## Simulation invariant

Every policy is replayed from fresh state against the same supplied counterfactual outcomes. The simulator never manufactures missing provider outcomes, token usage, or outcome quality. Demonstration fixtures are not empirical benchmark claims.

## Quality invariant

A contextual quality score is accepted only through a profile that names its benchmark ID, benchmark version, source, metric, and sample count. Structural validation does not by itself certify the scientific quality of an external benchmark.

## Adaptive-policy boundary

`adaptive_balanced` and `constrained_ucb` are reproducible offline research baselines. They are not enabled by the live HTTP gateway and carry no claim of superiority or optimality. Any production adoption requires a separate design decision and benchmark evidence.

## Acceptance principles

- no paid API key required for the default test/simulation path
- all experiments reproducible from committed configs/traces or clearly documented external datasets
- protocol, capability, circuit, model, and quota-exhaustion constraints are hard feasibility gates
- missing observations remain missing rather than being silently invented
- static production routing behavior is not silently changed by research instrumentation
- CI remains green on Python 3.11, 3.12, and 3.13

## Deferred dimensions

Vision, audio, and context-length capability classification remain outside v0.3 until the normalized request model can represent and test those dimensions losslessly. They are not release blockers.

## Research outputs enabled

The completed substrate supports reproducible studies of:

- cost-constrained latency minimization
- quality-constrained cost minimization
- quota-aware routing under bursty workloads
- contextual policy adaptation under hard feasibility constraints
- selected-feedback exploration versus static baselines
- sensitivity to capability constraints and provider failures

Any reported performance result must come from an actual committed experiment or documented reproducible dataset; implementation alone is not empirical evidence.
