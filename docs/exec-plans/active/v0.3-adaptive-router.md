# Execution Plan: v0.3 Adaptive Router

Status: active

## Objective

Evolve AgentMesh from a static weighted router into a reproducible constrained routing system that can support research-quality experiments over cost, latency, quality, reliability, and quota pressure without ever selecting a protocol- or capability-infeasible provider.

## Core invariant

Optimization happens only over the feasible provider set.

```text
all configured providers
  -> model + circuit constraints
  -> protocol-losslessness constraints
  -> capability constraints
  -> quota exhaustion constraint
  -> feasible providers
  -> policy / learned ranking
```

No later optimization stage may reintroduce a provider removed by a hard feasibility gate.

## Accounting invariant

`cost_hint` is a configured heuristic for the current static routing score. It is not observed spend. Observed runtime cost uses upstream-reported token counts plus explicitly configured token prices. Missing observations remain missing rather than being converted to zero or estimated from text length.

## Latency invariant

`latency_ewma_ms` remains the current live routing signal. p50/p95 are bounded recent-success evidence for diagnostics and simulation. Adding percentile measurement does not silently change the `latency` or `balanced` policy objective.

## Quota invariant

Configured request quota is a deterministic local control model. It counts outbound provider attempts and can remove an exhausted provider from the feasible set. It does not claim to mirror upstream billing, token-rate, or private rate-limit counters.

## Simulation invariant

Every policy is replayed from fresh state against the same supplied counterfactual outcomes. The simulator never manufactures missing provider outcomes, token usage, or quality observations. Demonstration fixtures are not empirical benchmark claims.

## Acceptance principles

- no paid API key required for the default test/simulation path
- all experiments reproducible from committed configs/traces or clearly documented external datasets
- protocol, capability, circuit, model, and quota-exhaustion constraints are hard feasibility gates
- missing usage/quality observations remain missing rather than being silently invented
- routing decisions expose enough diagnostics to explain why a provider was eligible and how it was ranked
- CI remains green on Python 3.11, 3.12, and 3.13

## Research outputs enabled by this plan

Once benchmark profiles exist, the repository can support reproducible comparisons such as:

- cost-constrained latency minimization
- quality-constrained cost minimization
- quota-aware routing under bursty workloads
- regret of adaptive policies versus static baselines
- sensitivity to capability constraints and provider failures

Any reported result must come from an actual committed experiment or reproducible external dataset; this plan does not predeclare performance gains.
